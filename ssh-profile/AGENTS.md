# Использование ssh-profile моделью

Этот каталог — самодостаточный комплект подключения. Сначала прочитай `README.md`,
при необходимости `GUIDE.md`. Правила текущего проекта и инструкции оператора
имеют приоритет; наличие комплекта не разрешает произвольные изменения сервера.

## Порядок работы

1. Работай из корня принимающего проекта, где лежит каталог `ssh-profile/`.
   Не обращайся к прежнему проекту, пользовательским home или глобальным конфигам.
2. Используй Python 3.11+ и виртуальное окружение текущего проекта. Зависимости —
   `ssh-profile/requirements.txt`. Для SSH требуется Linux/WSL с OpenSSH.
3. Установку зависимостей выполняй только в рамках разрешённого задания, локально;
   TMPDIR/TMP/TEMP и cache направляй в `./temp/`. При смене cwd перенастраивай пути.
4. Проверь, что runtime `temp/` и `.venv/` игнорируются Git принимающего проекта.
   `.gitignore` этого каталога уже исключает рабочие профили внутри него.
5. Запусти `python ssh-profile/server_access.py validate` — без сети.
6. В рамках задания на подключение запусти `python ssh-profile/server_access.py check`.
   Эта проверка выполняет только id и sudo -n id; на сервере не меняет настройки.
7. Для Ansible запусти `python ssh-profile/server_access.py ansible --output-dir temp/ssh-profile-session`.
   Каталог должен быть новым. Используй сгенерированный inventory только для
   явно поставленных оператором задач. Повышение прав включай только где необходимо.

## Доступ и безопасность

- Рабочий профиль — `server-access.local.yml` рядом со скриптом; параметры подключения
  не нужно заново запрашивать или печатать в чат. Не публикуй его в Git.
- Не читай `.env`, `.env.*`, `*.pem`, `*.key` и закрытые ключи. В комплекте нет паролей.
- Ключ пользователя должен быть загружен в локальный SSH-agent. При отсутствии
  агента сообщи о недоступности `SSH_AUTH_SOCK` и попроси оператора настроить окружение.
  Не ищи сокеты/ключи вне проекта и не запускай пользовательские startup-скрипты.
- Ссылка на сокет агента — машинно-зависимое runtime-значение, не часть переносимого
  каталога. Если оператор дал такую ссылку внутри текущего проекта, её можно передать
  через `--agent-socket-file`; не переносить её в другой проект/на другой компьютер.
- Не отключай host-key checking, не заменяй доверенный host key автоматически,
  не включай парольный fallback и agent forwarding. При несовпадении ключа остановись.
- Не считай успешный check разрешением запускать bootstrap/hardening, менять
  пользователей, firewall, пароли, сервисы или приложения.
- Не используй перенесённые старые runtime inventory/ssh_config. Создавай новые
  внутри `temp/` текущего проекта: они содержат локальные абсолютные пути.

## Перенос

Копируется весь каталог `ssh-profile/` вместе с рабочим `server-access.local.yml`
и скрытым `.gitignore`. Git clone не переносит игнорируемый рабочий профиль:
оператор должен передать его отдельно внутри этой же папки доверенным способом.
Закрытый ключ, .venv, runtime temp и сокет агента переносить нельзя.
Все необходимые инструкции, зависимости, шаблон и тесты находятся здесь.
